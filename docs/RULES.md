# 라운지 · 동작 규칙

화면을 봐도 알 수 없는 규칙을 모았다. 전부 코드에서 뽑았고(2026-09-22, `server/writes.js` 기준),
줄 번호는 그 근거다. 규칙을 바꾸면 코드와 이 문서를 같이 고친다.

화면이 어떻게 생겼는지는 라이브(`pudufu-lounge.vercel.app`)가, 프드프와 무엇을 주고받는지는
`docs/API.md` 가, 왜 이렇게 설계했는지는 프로토타입 하단 스펙 시트가 말한다. 이 문서는 **"무엇이
허용되고 무엇이 막히는가"** 만 다룬다.

---

## 0. 세 가지 원칙

1. **역할은 계정이 아니라 라운지에 붙는다.** 한 강의의 관리자가 옆 강의 라운지에서는 수강생일 수 있다.
   (`lounge_member.role`)
2. **삭제는 물리 삭제가 아니다.** 글 · 댓글 · 카테고리 모두 `deleted_at` 을 찍는다. 지운 것은 화면에서만 사라진다.
3. **프드프에서 온 값은 라운지가 고치지 않는다.** 계정 · 구매 · 만료일 · 시청 기록 · 피드백권 잔여의 원본은 프드프다.
   라운지는 읽고, "썼다"는 사실만 남긴다. (`ext_*` 표, `account.js`)

## 3. 강의 · 진도 · 과제

| 규칙 | 근거 |
|---|---|
| 강의 구조는 **섹션 → 레슨**(영상 하나). 프드프가 원본 — 라운지는 읽기만. **화면에서는 섹션을 '챕터' 라고 부른다**(수강생에게 익숙한 말). 코드 · DB · API 는 섹션 | `account.js course()`, `ext_section` · `ext_lesson` |
| **진도는 시청에서 나온다.** 레슨 완료 = 끝까지 봄(`is_complete`), 섹션 % = 완료 레슨 / 레슨. 스스로 체크하는 것이 없다 | `present.js` sections, `ext_watch` |
| 라운지 플레이어에서 본 것은 15초마다 · 멈출 때 · 끝날 때 서버로(원격이면 프드프로) 보고한다. 5초 미만은 시청이 아니다. 본 위치는 뒤로 물러나지 않고, 완료는 거두지 않는다 | `markWatched()`, `lounge.js reportWatch` |
| **이어보기** = 가장 최근에 본 레슨(미완료 우선). 본 게 없으면 첫 섹션 첫 레슨 | `present.js resume` |
| 섹션 **게시/비공개**는 라운지 관리자가 정한다(행이 없으면 공개). 순차 잠금 · 마감 없음 | `setSectionPublished()` |
| 비공개 섹션은 수강생의 목록 · 검색 · 과제 고르기 · 진행률에서 빠진다. 관리자에게는 보인다 | `liveSections()` |
| **과제는 레슨에 붙는다.** 관리자가 레슨마다 N개 붙이고, 제목 + 질문 1~8개(빈 질문 불가) | `addTask()` · `editTask()` · `cleanQs()` |
| 과제 하나에 한 사람이 내는 글은 **한 편**. 다시 내면 앞 글을 지우고(soft delete) 새로 쓴다 — 화면이 덮어쓰기를 먼저 묻는다. DB 유니크가 두 편을 막는다 | `createPost()`, `uq_post_task_user` |
| 과제 글은 어느 과제에 낸 답인지(`task_id`)가 있어야 한다. 이 라운지의 과제여야 한다 | `createPost()` |
| 답변은 질문 문구와 함께 저장된다(스냅샷). 양식을 고쳐도 옛 제출물은 "그때 무엇에 답했는지" 가 남는다 | `post_answer.question` |
| 제출 글이 있는 과제는 지울 수 없다 | `deleteTask()` |
| **자료**는 파일(올린 것) 또는 링크. 링크는 주소 정규화 + 내부 주소 차단 | `addMaterial()` |
| 수강 기간이 끝난 사람은 강의를 보지 못하고 과제를 낼 수 없다 (스태프는 예외) | `checkExpiry()`, `watchLocked()` |
| 섹션 · 레슨 · 영상 · 타임라인 · 교안을 라운지에서 **만드는 것은 로컬 개발에서만**. 연결 뒤에는 프드프에서 온다 — 여기서 고치면 다음 동기화 때 덮인다 | `onlyLocal()` |
| 마감 · 정시/지각 · 카운트다운은 **없다** | — |

## 4. 피드백권

| 규칙 | 근거 |
|---|---|
| 잔여의 원본은 프드프. 라운지는 읽고, "썼다" 는 기록(`feedback_pass_use`)만 남긴다 | 72–83 |
| **글을 올리는 시점에 1장 차감.** 답이 오지 않아도 돌려주지 않는다 | 72–83, 176 |

## 10. 화면 규칙 (서버가 아니라 화면이 지키는 것)

- 글 목록은 30편씩, '더 보기' 로 이어진다. 고정 글은 첫 묶음 맨 위.
- 검색은 서버에서 한다 — 화면에 실린 30편 밖도 찾는다. 글 · 댓글 · 강의 · 교안 · 멤버.
- 브라우저 팝업(`alert` · `confirm`)을 쓰지 않는다. 확인은 카드 안에서 묻는다.
- 게시 단추는 보내는 동안 잠긴다. 그래도 두 요청이 떠나면 서버가 하나로 본다(2절).
- 뒤로가기는 라운지 안에서 움직인다. 탭 · 강의실(섹션 · 레슨 · 열린 과제) · 열린 글이 주소에 남는다(`?t=` `?s=` `?l=` `?k=` `?p=`).
- 강의실 본문은 영상 → 타임라인 → 교안. 두 토글은 기본 접힘, 타임라인 줄과 교안 속 `12:30` 은 눌러서 그 시각으로. 레슨 설명란은 화면에 두지 않는다(검색에만 쓴다).
- 강의실 왼쪽 카드 머리의 **목차** 단추를 누르면 **전체 목차**(섹션 전부와 그 아래 레슨 전부)가 내려온다. 레슨 줄 → 그 레슨, 섹션 줄 → 그 섹션의 첫 레슨. 강의 탭으로 나가지 않고 오간다.
- 필터 · 정렬은 주소에 남기지 않는다.
