# 프드프 라운지

강의별 커뮤니티 라운지. 기획을 화면으로 옮긴 **프로토타입**과, 그것을 실제로
돌리기 위한 **스키마 · 시드 · API 계약**이 같이 있다. 빌드 도구는 쓰지 않는다.

| 파일 | 내용 |
|---|---|
| `lounge-web-prototype.html` | **프로토타입.** 커뮤니티 · 강의 목록 · 강의 상세 · 관리 4화면 |
| `web/src/lounge.css` | 스타일 **원본**. Tailwind 토큰 + 컴포넌트 |
| `web/assets/lounge.css` | 빌드 결과. **프로토타입과 앱이 같은 파일을 쓴다** |
| `web/assets/lounge.js` | 화면과 동작. 〃 |
| `web/assets/data-mock.js` | 예시 데이터. 앱에서는 서버가 같은 모양으로 채운다 |
| `db/schema.sql` | 스키마(PostgreSQL). 라운지 12개 + 프드프 캐시 8개 |
| `db/seed.sql` | 시드. `data-mock.js` 에서 생성된다 |
| `server/` | 라운지 서버(Node.js). `account.js` 가 프드프와의 경계다 |
| `docs/API.md` | API 계약. 프드프에 요청할 5개 + 라운지 자체 |
| `DESIGN.md` | 디자인 토큰. `pudufu.net` 에서 추출 |
| `lounge-prototype.html` | 460px 모바일 컬럼 선행 버전. 웹 버전으로 대체됨 |

## 프로토타입은 스테이징이다

기능을 바꿀 때는 **프로토타입에서 먼저 확인하고** 확정되면 앱에 넣는다.
서버 없이 파일만 열면 도니까 가장 싸게 볼 수 있다.

그러려면 두 벌이 되면 안 된다. 그래서 CSS 와 클라이언트 JS 는 **한 벌만** 두고
프로토타입과 앱이 같이 쓴다. 다른 것은 데이터가 어디서 오느냐뿐이다.

```
프로토타입   data-mock.js  →  window.LOUNGE_DATA  →  lounge.js
앱           서버           →  window.LOUNGE_DATA  →  lounge.js
```

`lounge.js` 는 둘 중 어느 쪽인지 알지 못한다.

예시 데이터를 고쳤으면 시드를 다시 만든다.

```
npm run seed
```

## 스타일 — Tailwind

3.0 이 Tailwind 를 쓰므로 같은 어휘를 쓴다. `DESIGN.md` 의 토큰을 `@theme` 에
등록해 두었으므로 `bg-brand` `text-slate` `rounded-card` `tablet:` `max-w-page`
같은 유틸리티가 그대로 나온다.

`.post` `.chip` `.seg` 처럼 **이름이 있는 컴포넌트는 클래스로 둔다.** 유틸리티로
풀면 마크업만 지저분해진다. 레이아웃 미세조정과 새로 붙이는 것은 유틸리티로 쓴다.

```
npm install
npm run css          한 번 빌드
npm run css:watch    고칠 때마다
```

빌드 결과(`web/assets/lounge.css`)를 저장소에 같이 넣는다. 프로토타입이
스테이징이라 **파일만 열면 돈다**를 지켜야 하기 때문이다. 빌드는 고치는
사람만 돌린다. 3.0 도 번들러 없이 Tailwind 를 쓰므로 운용 방식이 같다.

> 빌드한 뒤 화면이 그대로면 브라우저 캐시다. 강력 새로고침(`⌘⇧R`).

## DB

**PostgreSQL** 이다. 운영은 Supabase 를 쓰되 **관리형 Postgres + Storage 로만** 쓴다 —
Auth · RLS · 클라이언트 직결은 쓰지 않는다. 그래야 나중에 어디로든 옮길 수 있고,
`window.LOUNGE_DATA` 이음새도 지켜진다.

```
createdb lounge
psql -d lounge -f db/schema.sql
psql -d lounge -f db/seed.sql
```

시드는 불러오는 시점 기준 상대 시각으로 들어가므로 며칠 뒤에 넣어도
&lsquo;어제 올라온 글&rsquo;과 &lsquo;이번 주 미제출&rsquo;이 그대로 말이 된다.

**숫자가 화면과 일치하는지 확인했다.** 수강생 24 · 대기 피드백 3 · 답 없는 과제 8 ·
이번 주 미제출 12 · 7일 이상 조용 4 · 어제 글 5 · 어제 입장 2 · 어제 강사 피드백 3,
그리고 주차별 이탈 퍼널까지 프로토타입 화면과 같다.

나중에 MySQL 로 되돌릴 일이 생기면 `make-seed.js` 의 방언 함수 세 줄만 바꾸면
시드는 자동으로 따라온다. 스키마는 손으로 번역한다(테이블 20개).

## 서버

```
npm install
npm run dev          http://localhost:4000
```

프레임워크를 쓰지 않는다. 서버가 하는 일이 셋뿐이라서다 — 로그인 확인,
DB 에서 화면 데이터 만들기, 쓰기 받기. 렌더는 `lounge.js` 가 브라우저에서 한다.

| 파일 | 하는 일 |
|---|---|
| `server/account.js` | **프드프와의 경계.** 계정 · 구매 · 시청 기록 · 피드백권 · 강의를 받아 온다. `PUDUFU_MODE=local` 이면 `ext_*` 캐시만 읽고, `remote` 면 같은 함수가 HTTP 로 받아 온다 — 부르는 쪽은 그대로다 |
| `server/queries.js` | SQL 을 전부 모아 둔다. 흩어지면 DB 를 바꿀 때 찾아다녀야 한다 |
| `server/present.js` | DB 행을 `window.LOUNGE_DATA` 모양으로 옮긴다 |
| `server/render.js` | 프로토타입 마크업을 그대로 쓰고 목업 자리에 서버 데이터를 끼운다 |

`GET /l/data.json` 으로 화면이 쓰는 데이터를 그대로 볼 수 있다.
`GET /l/sync-weeks` 는 시청 기록에서 주차를 다시 계산한다(하루 한 번이면 충분).

쓰기(글 · 과제 · 댓글 · 반응 · 삭제)는 DB 로 간다. **권한은 `server/writes.js` 가
다시 판정한다** — 클라이언트의 `can()` 은 무엇을 보여줄지만 정한다.

**로그인은 아직 개발용 고정 사용자다.** SSO 가 붙으면 `server/index.js` 의
`viewer()` 한 곳만 바뀐다. `DEV_USER_ID=26 npm run dev` 로 관리자 시점을 볼 수 있다.

프로토타입의 **역할 전환기는 앱에 없다.** 앱에서 역할은 `lounge_member` 가
정하고 서버가 판정한다 — 브라우저에서 바꿀 수 있으면 안 된다.

## 어디에 만드나

라운지는 **프드프와 별도 서비스**로 돈다. 계정 · 구매 · 시청 기록 · 강의만
프드프에서 받아 오고 나머지는 전부 라운지가 갖는다.

그래서 프드프 개발자에게 요청할 것은 **API 5개뿐**이다 (`docs/API.md` 1부).
라운지 전체를 만들어 달라고 하지 않으므로 일정이 그쪽 로드맵에 묶이지 않는다.

영상은 Cloudflare Stream 에 있고 허용 도메인으로 막혀 있으므로,
라운지 도메인을 목록에 추가하면 그대로 재생된다.

## 보는 법

```
open lounge-web-prototype.html
```

`file://` 로 열어도 되지만, 유튜브 임베드는 로컬 서버로 띄워야 재생된다.

```
python3 -m http.server 8000
```

## 기획 출처

노션 `Skool.com 에서 프드프로 가져올만한 자산`. 커뮤니티 본질 정의부터 P1 여덟 항목까지 담겨 있다.
각 HTML 파일 하단의 스펙 시트에 P1 항목과 화면 요소의 대응표가 들어 있다.

핵심은 **게시판을 필터로 대체**하는 것이다. 프드프 현재 라운지 좌측 사이드바의 게시판
(자유 커뮤니티 / 릴스 피드백 / 올인원 AI 피드백)을 없애고, 카테고리 · 보기 · 회차 · 정렬을
동시에 걸 수 있는 필터 칩으로 옮겼다. 화면 전환이 사라지고 조합이 생긴다.

## 세 시점

상단바 우측 셀렉터로 **수강생 · 강사 · 관리자**를 오갈 수 있다. 실제 제품에는 없는 데모 장치이고,
같은 화면이 권한에 따라 어떻게 달라지는지 한자리에서 보려고 둔 것이다.

| 역할 | 보이는 것 |
|---|---|
| 수강생 | 커뮤니티 · 강의. 글쓰기 창에 공지 · 챌린지 없음 |
| 강사 | + 관리 탭의 대시보드 (피드백 요청 · 오늘 챙길 사람 · 어제 올라온 글) |
| 관리자 | + 주차별 이탈 퍼널 · 어제 커뮤니티 요약, 그리고 권한 · 필터 · 게시물 관리 |

멤버 정보는 **프드프 계정**을 그대로 따른다. 닉네임은 계정이, 기수는 강의 구매 데이터가 정하므로
라운지에서 고치지 않는다. 관리 화면에서 바꿀 수 있는 것은 역할 하나뿐이다.
(학원 이름은 프드프에 입력받는 창이 없어 열 자체를 두지 않았다.)

역할은 **계정이 아니라 라운지에** 붙는다. 관리 탭은 지금 보고 있는 라운지를 맡은 사람에게만 열리고,
필터 관리도 그 라운지 하나만 만진다.

`피드백 요청`은 따로 세운다. 과제에 댓글을 다는 건 선의지만 콘텐츠 피드백은 수강생이
**피드백권을 쓰고 기다리는 요청**이라, 답이 안 가면 권만 없어진다. 며칠째 기다리는지가 붙는다.

카테고리를 더하고 빼는 자리는 **필터 관리**다. 이 제품에서 카테고리가 곧 필터 칩이기 때문이다.
지우기는 미사용 칸에서만 되고, 글이 남아 있거나 다른 라운지가 쓰고 있으면 막힌다.
`과제`·`콘텐츠 피드백`은 뒤에 동작(미션 양식·피드백권)이 붙어 있어 지울 수 없다.

대시보드에는 **보고 나서 오늘 할 일이 바뀌는 숫자만** 둔다. 총 가입자·누적 게시물·평균 진도율은
어제와 오늘이 같으므로 뺐다. 강사 화면은 지표가 아니라 명단이다 — 이름을 누르면 그 글로 간다.

숫자는 전부 피드·명부를 그때그때 센 값이라 다른 화면과 어긋나지 않는다.
권한이나 필터를 바꾸면 커뮤니티 화면이 저장 버튼 없이 즉시 따라 바뀐다.

`어제 커뮤니티 요약`은 기획안 9장이다. 카카오가 봇 연결을 막아 자동 발송이 안 되므로,
문장을 미리 만들어 두고 관리자가 `복사`해서 오픈채팅방에 붙여넣는다.

## 디자인 시스템

`pudufu.net` 에서 추출했다. 토큰과 근거는 [`DESIGN.md`](DESIGN.md) 에 있다.

- 브랜드 블루 `#1F5AF2` 하나, 나머지는 Tailwind 그레이 스케일
- 의미색은 연한 면 + 같은 계열 진한 글자 쌍으로만 쓰고 테두리를 두르지 않는다
- 그림자는 `0 1px 3px rgba(0,0,0,.06)` 하나. 카드 경계는 `1px #F3F4F6` 선이 맡는다
- 서체는 Noto Sans KR 하나. 숫자 전용 페이스 없음, 자간 조정 없음
- UI 에 이모지를 쓰지 않는다. 아이콘은 인라인 SVG, 아바타는 이니셜

**시각 언어만 가져오고 정보구조는 가져오지 않았다.** 현재 `pudufu.net/community` 는 좌측에
게시판 4개를 세로로 두고 글쓰기를 하단 고정 바에 둔다. 노션 기획 7장이 문제로 지목한 구조라,
게시판은 필터 칩으로, 하단 입력 바는 피드 최상단 글쓰기 창으로 바꿨다. 벗어난 지점은
각 파일 하단 스펙 시트에 이유와 함께 적어 두었다.

## 주의

Noto Sans KR 은 Google Fonts 에서 받는다. CSP 로 외부 스타일시트를 막는 환경에서는
폴백(-apple-system / Apple SD Gothic Neo)으로 떨어진다. 로컬이나 자체 호스팅에서는 정상이다.

피드 · 검색 · 리더보드의 이름과 수치는 전부 예시 데이터다.
